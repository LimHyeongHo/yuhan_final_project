## 2. 목적

카카오 도서 검색 및 Google Books 표지 보강 과정에서 발생하는 외부 시스템 예외를 안전한 내부 오류로 변환하고, 예외 객체의 `e.getMessage()`가 API 응답·리다이렉트 URL·화면에 직접 노출되지 않도록 한다.

모든 API 오류는 기존 전역 계약인 `ErrorCode`, `CustomException`, `ErrorResponse`, `GlobalExceptionHandler`를 사용해 일관된 형식으로 반환한다. 서버 로그에는 장애 조사에 필요한 최소 정보만 기록하고 API 키, 인증 헤더, 외부 응답 본문, 스택 내부 정보는 사용자에게 공개하지 않는다.

## 3. 기준 원칙

### 3.1 `getMessage()` 사용 구분

다음 사용은 허용한다.

- `ErrorCode.getMessage()`: 개발자가 미리 정의하고 검토한 사용자용 메시지
- `CustomException.getMessage()`: 생성 원인이 `ErrorCode`로 제한된 경우
- 알림·시뮬레이션 엔티티의 `getMessage()`: 예외 객체가 아닌 검증된 업무 데이터
- 서버 내부 구조화 로그의 예외 객체 전달: 로그 접근 권한과 보존 정책이 적용되고 비밀정보가 포함되지 않는 경우

다음 사용은 금지한다.

- `catch (Exception e)` 이후 `e.getMessage()`를 응답의 `message` 또는 `error`에 저장
- 외부 API 예외의 `e.getMessage()`를 프론트엔드에 전달
- `e.getMessage()`를 결제 실패 등 브라우저 리다이렉트 URL에 포함
- 외부 예외 원문을 `System.out`, `System.err`, `printStackTrace()`로 출력
- 마스킹 성공 여부에 의존해 외부 예외 원문이나 응답 본문을 운영 로그에 기록
- 예외 원문을 새로운 `RuntimeException` 메시지에 이어 붙인 뒤 상위 계층에서 응답으로 노출

### 3.2 사용자 메시지와 운영 로그 분리

- 사용자 메시지는 `ErrorCode`에 정의된 고정 문구만 사용한다.
- 운영 로그는 내부 오류 코드, 외부 HTTP 상태, 예외 클래스, 요청 추적 ID만 기록한다.
- 검색어는 기본적으로 로그에 기록하지 않는다. 조사에 꼭 필요하면 길이를 제한하고 제어 문자를 제거한 값 또는 단방향 해시만 사용한다.
- 카카오 REST API 키, `Authorization` 헤더, 세션 쿠키, 결제 키, 인증서·개인키는 어떤 로그에도 기록하지 않는다.

## 4. 현재 구현 진단

### 4.1 카카오 검색 경로

현재 `KakaoBookSearchService`는 다음 항목을 이미 충족한다.

- 연결 3초, 읽기 5초 타임아웃 적용
- 카카오 401·403, 429, 5xx, 연결 실패를 서로 다른 내부 오류로 변환
- 외부 예외 원문 대신 고정된 사용자 메시지 사용
- 로그에 상태 코드·예외 클래스만 기록
- API 키 미설정 시 키 값을 포함하지 않는 오류 발생
- 정가 재조회 실패 시 상품 검증을 중단하지 않고 `originalPrice`로 대체할 수 있도록 `null` 반환

다음 항목은 개선이 필요하다.

- `NaverSearchController`가 `BookSearchException`을 직접 잡아 `{code, error}` 형식으로 반환한다.
- 빈 검색어가 `IllegalArgumentException`과 `e.getMessage()`를 통해 반환된다.
- 카카오 오류가 전역 `ErrorResponse`의 `success`, `code`, `message`, `timestamp`, `path` 형식을 사용하지 않는다.
- 프론트엔드는 표준 `message`가 아니라 기존 `error` 필드를 우선 사용한다.
- 컨트롤러 이름과 남아 있는 네이버 검색 분기가 현재 도서 검색 공급자를 정확히 표현하지 않는다.

### 4.2 전역 `e.getMessage()` 노출 현황

| 구분 | 주요 파일 | 현재 문제 | 처리 우선순위 |
|---|---|---|---|
| 인증·PKI | `PkiController`, `CAController`, `CertificateSessionController` | 예외 원문을 `error` 또는 `message`로 반환 | P0 |
| 회원 | `MemberInfoController` | 프로필·재발급·탈퇴 실패 원문 반환 | P0 |
| 외부 상품 API | `NaverSearchService` | 외부 예외 원문을 응답과 표준 오류 출력에 사용 | P0 |
| 테스트 인증 API | `PkiTestUtilController` | 예외 원문을 새 RuntimeException에 결합 | P0, 운영 비활성화 포함 |
| 결제 | `PaymentController` | `CustomException` 메시지를 URL 쿼리에 포함 | P1; 현재는 통제 문구지만 오류 코드 전달 방식으로 변경 |
| 알림 | `NotificationController` | 문자열 응답으로 전역 오류 계약 우회 | P1 |
| 관리자 작업 | `LegacyMigrationJobService` | 내부 예외 원문을 작업 상태에 저장·노출 가능 | P1 |
| PKI 서비스 로그 | `PkiService` | `System.err`, `printStackTrace()`, 원문 결합 사용 | P1 |
| 블록체인 공급자 | `BlockchainService` | 외부 노드 오류 원문이 상태 응답·저장값으로 전파될 가능성 | P1, 별도 점검 |

`ErrorCode.getMessage()`, `CustomException`에서 생성된 통제 메시지, `Notification.getMessage()`, `SecuritySimulation.getMessage()`는 Throwable 원문과 다르므로 일괄 제거 대상이 아니다.

## 5. 목표 오류 응답 계약

모든 REST 오류 응답은 다음 형식을 사용해야 한다.

```json
{
  "success": false,
  "code": "BOOK_SEARCH_TIMEOUT",
  "message": "도서 검색 서비스 응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요.",
  "timestamp": "2026-09-15T09:00:00",
  "path": "/api/search/product"
}
```

- `code`는 클라이언트 분기와 운영 추적에 사용하는 안정적인 값이다.
- `message`는 사용자에게 표시 가능한 한국어 고정 문구다.
- 외부 공급자의 상태 메시지와 응답 본문은 포함하지 않는다.
- HTTP 상태는 실제 실패 성격과 일치해야 하며 항상 200 또는 항상 500으로 변환하지 않는다.

## 6. 카카오 도서 검색 오류 매핑

| 발생 조건 | 클라이언트 HTTP | 내부 코드 | 사용자 메시지 | 서버 처리 |
|---|---:|---|---|---|
| 검색어 누락·공백 | 400 | `BOOK_SEARCH_INVALID_QUERY` | 검색어를 입력해 주세요. | 외부 API 호출 금지 |
| 카카오 키 미설정 | 503 | `BOOK_SEARCH_NOT_CONFIGURED` | 도서 검색 서비스가 설정되지 않았습니다. 관리자에게 문의해 주세요. | ERROR 로그 및 운영 알림 대상 |
| 카카오 401·403 | 502 | `BOOK_SEARCH_AUTH_ERROR` | 도서 검색 서비스 인증에 실패했습니다. 관리자에게 문의해 주세요. | 외부 상태만 WARN 기록, 키 비노출 |
| 카카오 429 | 429 | `BOOK_SEARCH_QUOTA_EXCEEDED` | 도서 검색 요청이 많아 일시적으로 제한되었습니다. 잠시 후 다시 시도해 주세요. | 재시도 유도, 즉시 반복 호출 금지 |
| 카카오 5xx | 502 | `BOOK_SEARCH_UPSTREAM_ERROR` | 도서 검색 서비스에 일시적인 오류가 발생했습니다. 잠시 후 다시 시도해 주세요. | 제한적 재시도 또는 실패 반환 |
| 연결·읽기 시간 초과 | 504 | `BOOK_SEARCH_TIMEOUT` | 도서 검색 서비스 응답이 지연되고 있습니다. 잠시 후 다시 시도해 주세요. | 타임아웃 유지, 무한 대기 금지 |
| 그 밖의 외부 통신 오류 | 502 | `BOOK_SEARCH_UPSTREAM_ERROR` | 도서 검색 서비스에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요. | 예외 클래스만 기록 |
| 검색 결과 없음 | 200 | 해당 없음 | 검색 결과가 없습니다. | 빈 배열 반환 |

카카오의 401·403을 사용자 세션의 401·403으로 그대로 전달하면 안 된다. 해당 상태는 서비스 사용자의 인증 실패가 아니라 서버와 외부 공급자 사이의 인증 실패이므로 502로 매핑한다.

## 7. 기능 요구사항

### BOOK-ERR-001 전역 예외 체계 통합

- 우선순위: P0
- `ErrorCode`에 6절의 `BOOK_SEARCH_*` 코드를 추가한다.
- `KakaoBookSearchService`는 외부 예외를 `CustomException(ErrorCode)`로 변환한다.
- `NaverSearchController.searchProduct()`의 도서 분기에서 `IllegalArgumentException`과 `BookSearchException` 직접 catch 및 수동 `Map` 응답을 제거한다.
- 예외 응답은 `GlobalExceptionHandler`가 생성한다.
- `BookSearchException`이 더 이상 사용되지 않으면 삭제한다. 유지할 경우 전역 핸들러에서 동일한 `ErrorResponse` 형식으로 변환해야 한다.

인수 기준:

1. 카카오 검색 오류 응답이 모두 `success`, `code`, `message`, `timestamp`, `path`를 포함한다.
2. 오류 응답에 `error` 필드와 외부 예외 원문이 포함되지 않는다.
3. 빈 검색어 입력 시 카카오 API가 호출되지 않고 400을 반환한다.

### BOOK-ERR-002 검색과 정가 검증의 실패 정책 분리

- 우선순위: P0
- 판매자가 실행한 검색은 실패 원인을 6절의 코드로 사용자에게 반환한다.
- `VerificationService`가 호출하는 정가 재조회는 외부 장애 때문에 상품 기본 조회나 블록체인 해시 검증 전체를 실패시키지 않는다.
- 정가 재조회 실패 시 고정된 내부 코드만 로그에 남기고 `originalPrice` 대체 정책을 유지한다.
- 인증 실패·키 미설정·쿼터 초과는 운영자가 구분할 수 있어야 한다.

인수 기준:

1. 카카오 장애 중에도 저장된 상품의 기본 상세 조회가 성공한다.
2. 정가를 조회할 수 없으면 기존 `originalPrice`를 사용하고 외부 예외 원문은 응답하지 않는다.
3. 검색 화면에서는 결과 없음과 외부 장애가 서로 다른 UI로 표시된다.

### BOOK-ERR-003 안전한 로그

- 우선순위: P0
- `log.warn("... {}", e.getMessage())` 형태로 외부 예외 원문을 기록하지 않는다.
- 허용 로그 필드는 내부 오류 코드, 외부 HTTP 상태, 예외 클래스, 요청 추적 ID로 제한한다.
- 운영 로그에서 `KakaoAK`, 실제 REST API 키, `Authorization`, 외부 응답 본문이 검색되지 않아야 한다.
- 예외 객체 전체 로깅이 필요한 경우 비밀정보 포함 여부를 검증한 중앙 로깅 정책을 먼저 적용한다.

인수 기준:

1. 카카오 인증 오류·타임아웃 테스트 로그에 테스트 API 키가 나타나지 않는다.
2. 클라이언트 응답에 예외 클래스명, 스택, URI 내부정보가 나타나지 않는다.
3. `System.out`, `System.err`, `printStackTrace()`를 사용하지 않는다.

### BOOK-ERR-004 프론트엔드 오류 처리

- 우선순위: P1
- `ProductsRegisterPage`는 실패 응답의 `code`와 `message`를 읽는다.
- 백엔드·프론트 배포 순서가 분리된다면 전환 기간에만 `message ?? error` 호환 처리를 허용하고, 전환 완료 후 `error` fallback을 제거한다.
- 응답 본문 파싱 실패, 네트워크 단절, 요청 취소를 구분한다.
- 429는 재시도 안내, 503은 관리자 설정 안내, 502·504는 일시 장애 안내를 표시한다.
- 검색 버튼은 요청 진행 중 중복 실행되지 않고 `finally`에서 다시 활성화되어야 한다.

인수 기준:

1. 서버가 표준 오류를 반환하면 고정된 사용자 메시지가 표시된다.
2. JSON이 아닌 오류 응답에도 화면이 멈추지 않고 기본 메시지를 표시한다.
3. 실패 후 검색 버튼과 입력 상태가 정상적으로 복원된다.

### BOOK-ERR-005 Google Books 표지 보강 격리

- 우선순위: P1
- 카카오 결과 선택 후 실행되는 Google Books 표지 조회 실패는 선택한 도서 메타데이터를 초기화하지 않는다.
- Google 표지를 불러오지 못하면 카카오 썸네일 또는 현재 기본 이미지로 대체한다.
- Google 예외 원문도 카카오와 동일하게 클라이언트에 노출하지 않는다.
- 표지 조회 실패는 도서 등록 자체를 차단하지 않는다.

인수 기준:

1. Google Books 장애 시에도 제목·ISBN·저자·출판사·정가는 유지된다.
2. 이미지 요청 실패가 텍스트로 렌더링되지 않는다.
3. 표지 실패 후에도 상품 등록이 가능하다.

### GLOBAL-ERR-001 전역 직접 노출 제거

- 우선순위: P0
- 4.2절의 컨트롤러에서 `e.getMessage()`를 응답에 직접 넣는 코드를 제거한다.
- 예상 가능한 업무 오류는 구체적인 `ErrorCode`와 `CustomException`으로 변환한다.
- 예상하지 못한 예외는 다시 던져 `GlobalExceptionHandler`의 `INTERNAL_SERVER_ERROR`로 처리한다.
- 트랜잭션 메서드에서 예외를 catch해 응답으로 바꾸지 않는다. 불가피한 경우 rollback-only 처리와 고정 오류 변환을 함께 적용한다.
- 오류 응답을 직접 만드는 컨트롤러는 단계적으로 전역 핸들러로 통합한다.

인수 기준:

1. `error.put("error", e.getMessage())`, `response.put("message", e.getMessage())` 패턴이 운영 컨트롤러에서 0건이다.
2. 예상하지 못한 예외 응답은 항상 `INTERNAL_SERVER_ERROR` 고정 문구를 사용한다.
3. SQL·파일경로·외부 API 원문·키·인증 데이터가 응답에 포함되지 않는다.

### GLOBAL-ERR-002 리다이렉트 오류 코드화

- 우선순위: P1
- 결제 실패 리다이렉트에는 자유 형식 예외 메시지 대신 허용 목록 기반 오류 코드만 전달한다.
- 프론트 결제 실패 페이지가 오류 코드를 사용자용 문구로 매핑한다.
- 예외 메시지를 URL 인코딩하는 것만으로 안전하다고 판단하지 않는다.

인수 기준:

1. 결제 실패 URL에 스택·DB·외부 공급자 메시지가 포함되지 않는다.
2. 알 수 없는 오류 코드는 일반 결제 실패 문구로 표시된다.

### GLOBAL-ERR-003 운영·관리자 오류 정보 제한

- 우선순위: P1
- `LegacyMigrationJobService`와 블록체인 상태에는 원문 예외 대신 내부 오류 코드와 검토된 요약만 저장한다.
- 상세 스택은 서버 로그에서 요청 추적 ID로 조회한다.
- 관리자 화면이라는 이유만으로 비밀 키나 외부 공급자 원문을 노출하지 않는다.

## 8. 구현 순서

1. `ErrorCode.java`에 `BOOK_SEARCH_*` 코드 추가
2. `KakaoBookSearchService`의 예외를 `CustomException` 기반으로 전환
3. 검색 컨트롤러의 직접 catch·수동 오류 Map 제거
4. `ProductsRegisterPage.jsx`를 `code`·`message` 계약으로 전환
5. 카카오 서비스 및 검색 컨트롤러 테스트 추가
6. 인증·회원·CA 컨트롤러의 직접 `e.getMessage()` 노출 제거
7. 결제 리다이렉트와 관리자 작업 상태를 오류 코드 기반으로 전환
8. Naver·PKI·블록체인 외부 오류 로그를 구조화 로그로 교체
9. 전체 저장소 비밀정보·예외 원문 노출 회귀 검사

카카오 검색 경로를 먼저 완료해 표준 구현 예시로 사용한 후 다른 도메인에 동일 패턴을 확장한다.

## 11. 완료 조건

다음 조건을 모두 충족해야 완료로 판정한다.

1. 카카오 검색 오류가 전역 `ErrorResponse` 형식으로 반환된다.
2. 카카오 및 Google 외부 예외 원문과 API 키가 응답·로그에 노출되지 않는다.
3. 검색 결과 없음과 외부 장애가 구분된다.
4. 정가·표지 보강 장애가 상품 조회·등록·블록체인 검증 전체 장애로 확산되지 않는다.
5. 운영 컨트롤러에서 Throwable의 `e.getMessage()`를 직접 반환하는 코드가 제거된다.
6. 필수 테스트가 통과하고 정상 도서 검색·등록 기능에 회귀가 없다.

## 12. 범위 주의사항

- 본 문서는 오류 처리 계약을 정의하며 카카오 검색 결과 저장·캐시 이용 조건은 별도 데이터 정책으로 관리한다.
- 과거 마이그레이션 문서의 Google Books 후속 작업 및 카카오 썸네일 미사용 방침은 현재 구현과 다르다. 현재 코드는 카카오 썸네일을 즉시 표시하고 Google Books 표지를 우선 보강하는 흐름이므로 테스트도 현재 동작을 기준으로 한다.
- `NaverSearchController` 이름 변경과 사용 중지된 네이버 상품 검색 제거는 별도 정리 커밋으로 수행해 오류 처리 변경과 기능 제거를 한 커밋에 섞지 않는다.
